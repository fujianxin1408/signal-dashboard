# 自选信号

A 股自选股技术指标信号看板（RSI14 + BIAS6 组合触发）。

- 单文件静态页，数据内联，不依赖后端
- 每个交易日 **15:05（收盘确认）** 自动归档；盘中随时点「更新」按实时价重算（14:51 盘中档已于 2026-11-11 停用）
- 页面只有一个入口「更新」：不再有「实时 / 15:05」两个 tab，打开看到的就是最新一份快照，点「更新」才切到实时价重算的结果
- **只在 A 股交易时段自动刷新（9:30-11:30 / 13:00-15:00，工作日），每 10 分钟一次**：打开页面立刻算一次，之后每 10 分钟自动拉实时报价重算，页头标签显示倒计时；
  点该标签可关闭（选择记在 localStorage）。只在浏览器里算，不写 `data.json`、不产生提交、不推送
  - 收盘后、午休、周末打开页面**一个行情请求都不发**，只显示 `data.json` 里最近的收盘档；
    标签显示「↻ 仅交易时段 · 明日 9:30 开盘」这类提示，非交易时段的定时器降到 30 秒一次，只为等开盘
  - 页面一直开着跨进交易时段（开盘、午休结束）会立刻补刷一次，不等下一个 10 分钟
  - 判定按周一至周五 + 时段，不含交易日历：法定节假日页面仍会按点拉一次，但接口返回的是上一交易日收盘价，
    页面数字不变（要彻底不拉需要接交易所日历，收益不值）
- 46 只标的（含 515080 中证红利ETF 的稳健/高频两档策略行），买点/卖点均为**收盘价口径**的触发价，页面同时给出「还需跌 / 已低」的距离
- 参数均由历史回测选定，行内标注 `回测 N 笔 · 胜率 · 累计 · 止损`
- **大盘门控**：`bt.mkt=True`（金山办公、青岛啤酒、江西铜业）需要沪深300 > MA60；`bt.mkt="bear"`（诺力股份、华东医药）需要沪深300 < MA60。门控只在价格条件已触发时把「买入」降为「等待」，并在信号列标出原因；前端实时重算同口径

  `(ma60_floor, bias_price)`；两者贴在一起时区间为空，页面显示「贴线，无买点」，而不是给一个永远等不到的假买点
- 触发价口径（MA250 年线，2026-11 新增）：`MA250上` 同理给出年线下界；`MA250升`（年线高于 20 日前）也解成一个下界
  `C > 250·A − s249`，A 为 20 日前的 MA250。年线下行时这个下界会顶到乖离上界之上，区间自然为空——
  这正是「想等回调、但年线还没站上」的形态，页面买点列显示「≥年线门槛」并提示「站上才谈买点」；
  若现价已在年线之上、只是「再跌 N% 就破线」（海澜之家），下界不是买点，页面显示「再跌就破年线」且不给数字；
  中国平安是 `MA60上`（非年线），同类提示显示「再跌就破 MA60」。
  `MA250下`（森马服饰、诺力股份）方向相反，解成价格**上界**，不产生夹逼区间
- **价格小数位（2026-11-16 修正）**：普通 A 股最小变动 0.01 元，一律显示 2 位（海澜之家 6.17，不再是 6.170）；
  只有 ETF（中证红利 515080，最小变动 0.001）显示 3 位。旧版按「价格<10 元」猜 3 位，纯属显示假象，不影响计算。
- **复权口径差异（2026-11-13，海澜之家 600398）**：除重庆水务、圣农发展外，看板一律用**不复权**价（实盘软件看到的价），回测用**前复权**。

  前复权序列以最新价为基准，**最后一根收盘 = 实际收盘**，与实时报价同口径，因此买点价可直接照着挂单，
  前端 `hist` / `recalcRow` 算法一行都不用改；`data.json` 用 `fq="qfq"` 区分，行内标注「前复权口径」。
  另注：这只票的收益主要来自分红再投资推高的复权价，不能按「股息率 4.2% 折价」去给前复权曲线打折。

## 「更新」按钮怎么工作

旧实现是「点按钮 → 触发 GitHub Actions → 等 2 分钟 → 轮询 data.json」。这条链路有两个硬伤：
Actions 要重新 checkout、装依赖、抓全部标的，本身 1～2 分钟；cron 还会排队延迟。点下去像没反应。

现在改成**浏览器本地计算**：

1. `data.json` 每行预埋 `hist`（最近 300 根收盘，MA250 需 251 根）、每个档位预埋 `mkt.closes`（沪深300）。
   绝大多数标的是不复权，`fq="qfq"` 的行（重庆水务、圣农发展、内蒙华电、鲁泰A、浙能电力、上海环境、515080 稳健/高频两档等）整条是前复权，但最新一根等于实际收盘，与实时价同口径
2. 点「更新」→ `fetch('https://qt.gtimg.cn/q=sh600019,sz000895,...')` 一次拿全部实时价（`ACAO:*` 可直接跨域）
3. 用「预埋历史 + 今日实时价」在 JS 里重算 MA6 / BIAS6 / RSI14 / MA60 / MA250 / 买卖触发价
4. 1 秒内重绘，页头显示 `实时 09:53:45　基准 2026-11-11 09:51`

算法是逐行复刻 `ci/update_ci.py` 的（含 BIAS 闭式解、RSI 五日匀速反解、MA60/MA250 夹逼窗口），
全部标的逐字段比对过，与 Python 输出完全一致。所以本地算和收盘归档算不会打架。

保护：基准 `histDate` 距今超过 4 天（长假）就拒绝重算，提示「基准过旧」，宁可不算也不给错数。
交易时段（9:30-11:30 / 13:00-15:00）打开页面会自动算一次，不用手点；非交易时段打开就停在最近收盘档。

## 微信提醒（2026-11 新增，11-18 改为盘中实时）

- **交易时段每 15 分钟扫一次，一触发就推「盘中预警」**：北京时间 9:30-11:30 / 13:00-15:00，用 `intraday` 档；非交易时点（午休、收盘后）自动跳过，收盘档会兜底（`TRADING_ONLY=0` 可关掉时段限制）
- **每天 15:05 另推一次「收盘确认」**：最终以收盘价为准；盘中已推过的同一只票不再重复响，只补推盘中没出现过的新信号
- **默认只推「买入触发」**：卖出信号不发——持仓只存浏览器，服务端不知道谁持股，对空仓的人提醒卖出纯属噪音；要看卖出提醒就在看板填成本价（`NOTIFY_SELL=1` 可恢复旧行为）。没信号不打扰；周五收盘若整周静默，发一条「本周无信号」心跳——否则 token 过期这种事可能几周都发现不了（`HEARTBEAT=0` 可关）
- **live 档一律不推**：手动点「更新」、Actions 补跑都不会响，避免自己刷页面把自己吵到
- 去重记录在 `notify_state.json`，随仓库提交，**按天跨档**（同一只票当天只响一次，盘中/收盘不重复）；**推送失败不记账**，下一轮会自动重试，信号不会被吞掉
- 通道按环境变量择一，按优先级：`WXPUSHER_TOKEN`+`WXPUSHER_UID`（WxPusher → 微信，扫码即用）/ `SERVERCHAN_KEY`（Server酱 → 微信）/ `PUSHPLUS_TOKEN`（PushPlus → 微信）/ `DINGTALK_URL` / `FEISHU_URL` / `WECOM_URL` / `NTFY_TOPIC`
- 自测：`WXPUSHER_TOKEN=xxx WXPUSHER_UID=xxx python ci/notify.py --test`（也可在 Actions 里手动触发 `intraday` 档验证）

GitHub Actions 的 cron 本身有 5～75 分钟延迟，盘中 `*/15` 的任务实际常在 10~30 分钟后才跑，且高峰会排队合并——**所以“每 15 分钟”是上限频率，不是精确保证**。想要真正的秒级实时，需要常驻服务（Cloudflare Worker 定时触发），不能靠 GitHub cron。收盘档的 15:05 归档也常在 16:00 之后才跑（11-17 是 16:23），但对收盘价信号无影响（收盘后价格不再变）。

## 时点口径

GitHub Actions 的定时任务常有 5～40 分钟延迟，因此档位由**触发本次任务的 cron 决定**，而不是用运行时刻反推：

- 档位名固定为 `1505`，同时记录 `ts`（真实生成时刻）与 `skew`（延迟分钟数）
- **页面上不出现档位名**：只有「更新」一个按钮，卡片右上角显示「16:23 抓取」这种时刻，不再写「15:05 档 · 实际 16:23 生成（延迟 78 分）」——档位是排程细节，用户只需要知道数据几点抓的
- 15:05 的任务若延迟（GitHub cron 常见 5~40 分钟），`skew` 会如实记下延迟分钟数，不会假装准点
- 补跑（偏离目标 >25 分钟）不覆盖当天已抓到的真实档位，结果写入 `live` 档
