# 自选信号

A 股自选股技术指标信号看板（RSI14 + BIAS6 组合触发）。

- 单文件静态页，数据内联，不依赖后端
- 每个交易日 **15:05（收盘确认）** 自动归档；盘中随时点「更新」按实时价重算（14:51 盘中档已于 2026-11-11 停用）
- **只在 A 股交易时段自动刷新（9:30-11:30 / 13:00-15:00，工作日），每 10 分钟一次**：打开页面立刻算一次，之后每 10 分钟自动拉实时报价重算，页头标签显示倒计时；
  点该标签可关闭（选择记在 localStorage）。只在浏览器里算，不写 `data.json`、不产生提交、不推送
  - 收盘后、午休、周末打开页面**一个行情请求都不发**，只显示 `data.json` 里最近的收盘档；
    标签显示「↻ 仅交易时段 · 明日 9:30 开盘」这类提示，非交易时段的定时器降到 30 秒一次，只为等开盘
  - 页面一直开着跨进交易时段（开盘、午休结束）会立刻补刷一次，不等下一个 10 分钟
  - 判定按周一至周五 + 时段，不含交易日历：法定节假日页面仍会按点拉一次，但接口返回的是上一交易日收盘价，
    页面数字不变（要彻底不拉需要接交易所日历，收益不值）
- 26 只标的，买点/卖点均为**收盘价口径**的触发价，页面同时给出「还需跌 / 已低」的距离
- 参数均由历史回测选定，行内标注 `回测 N 笔 · 胜率 · 累计 · 止损`
- **大盘门控**：`bt.mkt=True`（金山办公、青岛啤酒）需要沪深300 > MA60；`bt.mkt="bear"`（诺力股份）需要沪深300 < MA60。门控只在价格条件已触发时把「买入」降为「等待」，并在信号列标出原因；前端实时重算同口径
- **「持仓」列**：填自己的成本价，行内即时算出浮盈/浮亏、涨到卖点还能赚多少、止损价在哪里、现价距止损还有多远。
  止损幅度取该票回测里的 `stop`（如扬杰 10%）；回测显示不该设硬止损的票（如中国平安 `stop=0`），
  改用买点条件本身当风控线——**跌破 MA60 即趋势假设被推翻**。成本存在浏览器 `localStorage`，不上传、不同步、不进 `data.json`
- **持仓视图（2026-11-13）**：某行一旦填了成本价就视为已持仓，自动从「找买点」切到「管卖出 / 守止损」——
  不再显示买点价与「还需跌 x%」，第 5 列改显止损价（含距止损距离），信息条把卖出价、止损价做成放大置顶的两个色块，
  成本 / 浮盈 / 到卖点盈亏降为次要文字；未填成本价的行完全不变，清空即还原。成本价纯前端 localStorage，
  服务端与微信推送都不感知，因此推送侧仍按原始买卖信号发送
- 触发价口径：BIAS 用闭式解 `s5×(1+k)÷(5−k)`（价格下跌会同时拉低 MA6，直接用 ma6×(1+k) 会偏高）；RSI 按「5 日匀速走到目标」反解
- 触发价口径（MA60 趋势过滤）：买侧一旦混入 `MA60上` 条件，买点就变成「MA60 之上 + 乖离达标」的**夹逼区间**
  `(ma60_floor, bias_price)`；两者贴在一起时区间为空，页面显示「贴线，无买点」，而不是给一个永远等不到的假买点
- 触发价口径（MA250 年线，2026-11 新增）：`MA250上` 同理给出年线下界；`MA250升`（年线高于 20 日前）也解成一个下界
  `C > 250·A − s249`，A 为 20 日前的 MA250。年线下行时这个下界会顶到乖离上界之上，区间自然为空——
  这正是「想等回调、但年线还没站上」的形态，页面直接显示「贴线，无买点」；`MA250下`（森马服饰、诺力股份）方向相反，解成价格**上界**，不产生夹逼区间
- 回测口径：**信号当日收盘成立，次日开盘成交**（避免使用未来数据）

## 「更新」按钮怎么工作

旧实现是「点按钮 → 触发 GitHub Actions → 等 2 分钟 → 轮询 data.json」。这条链路有两个硬伤：
Actions 要重新 checkout、装依赖、抓 26 只票，本身 1～2 分钟；cron 还会排队延迟。点下去像没反应。

现在改成**浏览器本地计算**：

1. `data.json` 每行预埋 `hist`（最近 300 根不复权收盘，MA250 需 251 根）、每个档位预埋 `mkt.closes`（沪深300）
2. 点「更新」→ `fetch('https://qt.gtimg.cn/q=sh600019,sz000895,...')` 一次拿全部实时价（`ACAO:*` 可直接跨域）
3. 用「预埋历史 + 今日实时价」在 JS 里重算 MA6 / BIAS6 / RSI14 / MA60 / MA250 / 买卖触发价
4. 1 秒内重绘，页头显示 `实时 09:53:45　基准 2026-11-11 09:51`

算法是逐行复刻 `ci/update_ci.py` 的（含 BIAS 闭式解、RSI 五日匀速反解、MA60/MA250 夹逼窗口），
26 只标的逐字段比对过，与 Python 输出完全一致。所以本地算和收盘归档算不会打架。

保护：基准 `histDate` 距今超过 4 天（长假）就拒绝重算，提示「基准过旧」，宁可不算也不给错数。
交易时段（9:30-11:30 / 13:00-15:00）打开页面会自动算一次，不用手点；非交易时段打开就停在最近收盘档。

## 微信提醒（2026-11 新增）

- **每天 15:05 推「收盘确认」一次**（14:51 盘中预警已停用：盘中价随时变、信号收盘可能反转，噪音大于价值）
- 只推**买入触发 / 卖出触发**，没信号不打扰；周五收盘若整周静默，发一条「本周无信号」心跳——否则 token 过期这种事可能几周都发现不了（`HEARTBEAT=0` 可关）
- **live 档一律不推**：手动点「更新」、Actions 补跑都不会响，避免自己刷页面把自己吵到
- 去重记录在 `notify_state.json`，随仓库提交；**推送失败不记账**，下一轮会自动重试，信号不会被吞掉
- 通道按环境变量择一，按优先级：`WXPUSHER_TOKEN`+`WXPUSHER_UID`（WxPusher → 微信，扫码即用）/ `SERVERCHAN_KEY`（Server酱 → 微信）/ `PUSHPLUS_TOKEN`（PushPlus → 微信）/ `DINGTALK_URL` / `FEISHU_URL` / `WECOM_URL` / `NTFY_TOPIC`
- 自测：`PUSHPLUS_TOKEN=xxx python ci/notify.py --test`

GitHub Actions 的 cron 本身有 5～40 分钟延迟，所以「15:05 档」实际可能是 15:12 才推——对收盘价信号没有影响（当日结论不变），但别指望它卡在 15:05:00。

## 时点口径

GitHub Actions 的定时任务常有 5～40 分钟延迟，因此档位由**触发本次任务的 cron 决定**，而不是用运行时刻反推：

- 档位名固定为 `1505`，同时记录 `ts`（真实生成时刻）与 `skew`（延迟分钟数）
- 页面显示形如「15:05 档 · 实际 15:12 生成（延迟 7 分）」，延迟一目了然
- 15:05 的任务若延迟（GitHub cron 常见 5~40 分钟），`skew` 会如实记下延迟分钟数，不会假装准点
- 补跑（偏离目标 >25 分钟）不覆盖当天已抓到的真实档位，结果写入 `live` 档

## 文件

| 文件 | 作用 |
|---|---|
| `ci/update_ci.py` | 抓行情、算指标、写 `data.json`（参数表在顶部 `WATCH`） |
| `ci/notify.py` | 读 `data.json` → 判信号 → 去重 → 推微信 |
| `notify_state.json` | 推送去重记录（留住最近 5 天） |
| `build_site.py` | 把 `data.json` 内联进 `tpl.html` + `page.js`，生成单文件 `index.html` |
| `.github/workflows/signal.yml` | 定时 / 手动触发，跑完自动提交 |
| `worker.js` | 可选：Cloudflare Worker 代理，让「更新」顺带触发一次 Actions 归档（不配也能用） |
